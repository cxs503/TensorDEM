## Interpretation contract

1. The grade is a **static, heuristic** classification of assertion style. It is not a physical-validation statement and it never runs the solver.
2. `QUANTITATIVE` means *a number is compared against a tolerance or a reference*. It does not mean the reference behind it is independent or correct: a module checked against a hand-typed copy of its own output is still `QUANTITATIVE`.
3. `attribution` is `direct` when a test function body names the module, and `file` when the module only appears elsewhere in a test file (for example in a file-scope import). `file` attribution is coarse: it credits every test in that file, so treat it as weaker evidence.
4. `reference_hint_tests` counts test functions that both credit the module and mention `analytic`, `closed-form`, `literature`, `reference`, `hand calculation` or `benchmark`. It is a reviewer hint, not a guarantee.
5. Generated output in `docs/verification-evidence/` is excluded from the documentation scan, which keeps the ledger idempotent.

The companion register `docs/verification_debt_register.md` records the debts this ledger exposes, with proposed single-agent scopes.
