# Doc-evidence pointer resolution: 88 -> 27 dangling `code` pointers

`docs/doc_evidence_ledger.json` (produced by `scripts/audit_doc_evidence.py`) is this
repository's machine-readable claim → artefact ledger.  Its value is entirely in the
honesty of the `MISSING` bucket: a pointer that the auditor calls dangling has to be
*actually* dangling, otherwise real verification debt is invisible inside noise.

## 1. Defect: the auditor did not know how documentation cites Python modules

TensorDEM keeps its package at `src/tensordem/`, so the **import path** of a module is
`tensordem/ice_creep.py` while its **repo path** is `src/tensordem/ice_creep.py`.  Docs
use the import path (correctly — that is how a reader imports it), and package-internal
files are cited relative to the package (`freeze_bond/__init__.py`,
`contact_physics/__init__.py`).  The resolver only tried *repo root* and *document
directory*, so both forms resolved nowhere:

| citation form | example | was | is |
|---|---|---|---|
| import path | `tensordem/biaxial_shear_band.py` | MISSING | TRACKED → `src/tensordem/biaxial_shear_band.py` |
| package-relative | `freeze_bond/__init__.py` | MISSING | TRACKED → `src/tensordem/freeze_bond/__init__.py` |
| module promoted to package | `src/tensordem/freeze_bond.py` | MISSING | TRACKED → `src/tensordem/freeze_bond/__init__.py` |

A fourth class produced the same false positives: modules that later became packages
kept being cited by the old `module.py` path (`freeze_bond`, `segregation`).

## 2. Fix

`scripts/audit_doc_evidence.py::candidates` gained two extra candidate families, applied
**only to `.py` pointers** so the data/figure/doc buckets are untouched:

1. repo-layout prefixes `src/` and `src/tensordem/` for the token with any leading
   `../` removed (`tensordem/x.py`, `freeze_bond/__init__.py`);
2. package-promotion fallback: `X.py` → `X/__init__.py`.

Resolution order is unchanged (root, `../`-stripped, doc-relative first), so no
previously TRACKED pointer can change identity; the new candidates are appended and only
match files that exist **and are tracked by git**.  A file that genuinely does not exist
still classifies `MISSING` (pinned by
`tests/test_doc_evidence_resolution.py::test_resolution_never_invents_paths`).

## 3. Result (measured, not hand-copied)

| bucket | before | after |
|---|---|---|
| `code:MISSING` | 88 | **27** |
| `code:TRACKED` | 1312 | **1373** |
| `data:MISSING` | 500 | 500 |
| `figure:MISSING` | 654 | 654 |

61 false-positive pointers were re-attributed to tracked source, so the remaining
27 entries are the *real* backlog:

| class | count | meaning / remedy |
|---|---|---|
| audit-only script under `artifacts/…` never committed | 9 | board-audit deliverables published as claims, script lived only in the auditor's worktree → the audit is not re-runnable from a clone |
| module deleted or renamed away | 16 | e.g. `src/tensordem/dem3d_pair_search.py`, `src/tensordem/neighbor_search.py`, `src/tensordem/crushed_ice.py` — prose still cites them |
| prose/placeholder token | 2 | `run.py/validate.py`, `scripts/Y.py` — matcher artefacts, not evidence |

Artefacts: `artifacts/doc_evidence_resolution/resolution_audit.json`,
`artifacts/doc_evidence_resolution/fig_code_missing_before_after.png`.

## 4. Regression gate

`tests/test_doc_evidence_resolution.py` (5 tests) pins the three resolution rules, proves
the resolver cannot invent a path, and enforces a ceiling of `code:MISSING <= 27` so a new
document cannot silently add dangling claims.  The figure above is regenerated by this
document's build; the numbers in the tables are read from the ledger, not typed.

## 5. Limitations

* Only `.py` pointers were re-resolved; `data:`/`figure:` buckets still contain ~1150
  absent artefacts, most of which are regenerable (the ledger records a `producers` list
  per entry) — closing them needs the producing benchmarks to be re-run, not a resolver
  change.
* The ceiling is a snapshot of today's debt; it is a gate against regression, not a
  claim that the remaining 27 pointers are acceptable.
* No literature/anchor question is involved, so there is no "<3 % vs benchmark" number
  to report here; the acceptance quantity is the dangling-pointer count itself, which is
  exact.
