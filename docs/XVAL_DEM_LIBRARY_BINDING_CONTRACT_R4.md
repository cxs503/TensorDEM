# XVAL：TensorDEM 冻结绑定契约（第 4 轮）——契约自身的版本纪律与绑定方清单

锚点：`XVAL-DEM-LIBRARY-BINDING-FROZEN-CONTRACT`（题面「TensorPhysics 的 library-binding-frozen-contract 做法」）
域：通用 DEM 求解器绑定面（2-D `IceDEM` / 3-D `IceDEM3D`）
代码：`src/tensordem/binding_contract.py`（新增 lineage 段）、`tests/test_binding_contract_lineage.py`、
`scripts/xval_library_binding_contract_r4.py`
工件：`artifacts/xval_library_binding_contract/{manifest_v1.0.0.json, manifest_round3_unrecorded.json, result_r4.json, fig_*.png}`

## ① 背景：前 3 轮冻结的是「面」，没有冻结「面这份数据」

第 1/2 轮把 `IceDEM`/`IceDEM3D` 的**名字、签名、必需性、返回元组、单位、时钟规则、能力名、负断言**数据化，
用 `fingerprint()` + `FROZEN_FINGERPRINT` 钉死，并用 `verify()` 做「契约数据 ↔ 活体类」的内省比对；
第 3 轮用 `surface_ledger` 把每个公开成员逐条表态（2-D 11/11 冻结，3-D 8 冻 12 排除附理由），
消除「静默长出新成员」的洞。

两轮共同的方法论缺口是：**被冻结的那份数据本身可以被编辑，防住它的只有散文**（"要在同一 commit 重钉"）。
这不是假想——本轮开工核对 git 史即发现第 3 轮已经踩了：

| 轮次 | payload 内容 | `CONTRACT_VERSION` | 指纹 | 是否有发布记录 |
|---|---|---|---|---|
| 1/2 | 声明面 + 探针 + 变异矩阵 | `1.0.0` | `sha256:0cbfed8c…4105d` | 无（首次冻结） |
| 3 | 追加 `surface_ledger`（+31 条成员表态） | `1.0.0`（**未 bump**） | `sha256:048e4cf9…195cd`（**已换**） | **无** |

即：契约语义已经变了（新增 31 条冻结/排除表态），版本号还停在 `1.0.0`，仓库里没有任何机器可读的记录说明
「谁在什么时候为了什么改了冻结面」。绑定方（`TensorPhysics` 适配器、船舶平台驱动）因此**无法判断自己钉住的
那份契约是否还成立**——这正是 `TensorPhysics/docs/adapter-contracts.md` 之外的差集。

同时还有第二个更隐蔽的洞：`verify()` 是「契约 ↔ 活体类」比对，凡活体类表达不出来的元数据
（`units`、声明 `shape`/`dtype`、时钟容差、能力名、负断言、返回元组文案）**它一条都看不见**——
有人把 `dt` 的单位从 `s` 改成 `ms`，`verify()` 照样 `CONFORMS`（第④节 10/10 量化）。

本轮就是把这两件事补上：**契约自身的版本纪律（lineage）+ 绑定方可离线自证的清单（manifest）**。

## ② 方法

| 组成 | 内容 |
|---|---|
| `diff_contracts(old, new)` | 契约↔契约的**严重度分级**差分，纯数据、不导入 torch。逐条目比对 `state/properties/methods/params/clock/capabilities/explicitly_absent/surface_ledger`，输出 `change` 类 + `severity` |
| `CHANGE_SEVERITY`（封闭词表） | 45 个变更类 → `doc / additive / narrowing / breaking`。`units/shape/dtype/returns` 一律 `breaking`：「调用方式没变但物理量纲变了」比签名消失更危险 |
| `required_bump(findings)` | 严重度 → 最小合法 semver 档（`breaking→major`、`additive/narrowing→minor`、`doc→patch`）。「这次改动算不算 breaking」不再由人事后拍板 |
| `CONTRACT_HISTORY` + `check_lineage()` | 追加式发布链 `version → fingerprint → changes → bump`。检查：条目完整 / semver 合法且严格递增 / 指纹格式 / 版本与指纹不重复 / 变更类在词表内 / 首条必须是 `initial_freeze` / **声明的 bump 必须覆盖声明变更类隐含的 bump** / **链尾版本必须等于 payload 版本、链尾指纹必须等于 payload 指纹**（未记录的重钉 = `breaking`） |
| `export_manifest()` / `write_manifest()` | 绑定方钉住的工件：`{schema, contract_version, fingerprint, payload}` 单文件 JSON，可直接进消费方 CI |
| `check_consumer_manifest()` | 离线的消费方判定：清单自洽（payload 哈希 = 声明指纹）/ 版本与指纹是否在发布链中 / 与当前契约做 `diff_contracts`，输出 `CONFORMS` / `COMPATIBLE_ADDITIVE` / `DRIFT` + `required_bump` |
| `record_history_entry()` | 由「上一份 manifest + 新 payload」**自动导出**变更类与 bump；声明低于隐含要求时抛 `BindingContractError(status=UNDERSTATED_BUMP)`——人手写 `patch` 掩盖 `entry_removed` 会被拒 |
| CLI | `--lineage` / `--export-manifest` / `--check-manifest` / `--record-history --record-version --record-reason` |
| 基线工件 | `manifest_v1.0.0.json`（git `b5220992`：真·1.0.0 冻结）、`manifest_round3_unrecorded.json`（git `60c06be6`：第 3 轮未记录的重钉，保留为**缺陷证据**，不回填历史） |
| 受控变异 | `lineage_matrix()`：5 类发布链洞（版本未 bump / 重钉未记录 / bump 低报 / reason 缺失 / 未知变更类）+ 3 类清单洞（payload 被改写 / 未记录发布 / 只改单位不改名字）+ 2 个干净对照 |
| 盲区基线 | `_blindness_baseline()`：10 类**纯元数据**变异同时喂给 `verify()`（旧检查集）与 `diff_contracts()`（新检查集），量化旧检查集看不见的东西 |

本轮把 `CONTRACT_VERSION` 从 `1.0.0` 提到 `1.1.0`：变更类不是手写的，而是 `diff_contracts(v1.0.0 payload, 当前 payload)`
算出来的 `["surface_ledger_member_added"]`（31 条，全 `additive`）→ 隐含 `minor`，与声明一致。
因版本号本身在 payload 内，重钉后指纹变为 `sha256:7249bd99…d0482`（预期摩擦，见 ⑤-1）。

## ⑤ 注意点（踩到的坑）

1. **指纹 churn 是设计而非噪声**：`contract_version` 在 payload 内，任何版本 bump 都必然换指纹；因此 `diff_contracts()` **故意不比 `contract_version`**，否则消费方每次 diff 都会多一条噪声变更——版本一致性交给 `check_lineage()` 的链尾检查。
2. **历史不回填**：第 3 轮那次未记录的重钉**没有**被伪造成一条 `1.0.0 → 1.1.0` 之外的条目，而是把 `manifest_round3_unrecorded.json` 作为**缺陷证据**留在工件里，由 `check_consumer_manifest` 判 `DRIFT`（`manifest_version_not_in_history`）。诚实记录缺陷比补一条好看的账有价值。
3. **首个发布豁免覆盖检查**：`initial` 没有前驱，`implied=patch` 不该判它低报；但 `initial` 只允许出现在 index 0（否则 `history_bump_unknown`）。
4. **diff 不能替代 verify/probes**：`diff_contracts` 只回答「声明变了没有、算不算 breaking」；「声明的语义在活体类上还成立吗」仍由第 1 轮内省检查（73 条）+ 19 个行为探针负责，「数值对不对」仍由 ref-vs-got 基准负责。三者互补，缺一即盲。
5. **刻意保留的 7 类旧盲区**：`units/shape/dtype/clock 容差/capability/负断言/返回元组` 在 `verify()` 下仍是 0 finding（第④节基线行如实记录）；本轮不是修 `verify()`，而是新增一个能看见它们的检查集——把「旧检查集看不见」当作**测量结果**报出，而不是悄悄把旧检查集改绿。
6. **局限**：跨仓 CI 接线仍属消费方职责（本仓只提供 `export_manifest` 工件与 `check_consumer_manifest` 判定函数，不替 `TensorPhysics` 建流水线）；`surface_ledger` 的「排除」语义仍是「供应方不背书」，绑定方碰它照样算 GAP（第 3 轮性质，未变）。
7. **`_provenance` 字段**：基线 manifest 顶层带 `_provenance` 说明来源 commit，不属于 payload，不参与指纹（`fingerprint(payload)` 只覆盖 `payload`）。
