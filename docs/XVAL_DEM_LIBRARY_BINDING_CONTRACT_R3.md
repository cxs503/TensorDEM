## ① 案例与问题（为什么还要第 3 轮）

第 1 轮的契约把 **2-D/3-D 求解器的绑定面**（时钟、载荷形状/单位/语义、子步规则、重启入口）钉成
声明式契约 + sha256 指纹 + 内省校验 + 19 个行为探针，检测 7 类漂移 7/7（基线名字级清点 1/7）。
它自己写下的限制第 6 条是：

> 3-D 公开成员只冻结 40%，未冻结的物理诊断若被绑定方依赖，仍可能静默漂移。

这不是"文档不够"，而是**机制漏洞**：`IceDEM3D` 有 20 个公开成员，契约只认 8 个。在另 12 个里
新增/改名/删除任何东西，`verify()` 依旧 CONFORMS，也没有任何测试会红——漂移发生在冻结面之外。
第 2 轮补的是反方向（绑定方**调用**面 → 契约），也不覆盖"供应方悄悄长出新成员"。

本轮的判别性问题是：**"被冻结的"与"被清点的"能不能合成一件事**——冻结面的补集不再是未知，
而是**显式带理由的排除**，任何新成员都必须在本 commit 内被表态。

## ② 方法

| 组成 | 内容 |
|---|---|
| `surface_ledger`（契约数据） | 每个冻结条目新增一份清点表：`name -> {"disposition": "frozen"}` 或 `{"disposition": "excluded", "reason": ...}`。2-D 11/11 冻结；3-D 8 冻 + 12 排除（物理诊断，逐条理由） |
| `public_members(cls)` | 公开面枚举（callable / property，忽略 `_` 前缀）——机器枚举，不手抄 |
| `audit_surface(target, entry)` | 逐成员分类，产出 `public_member_unclassified`（未表态，breaking）、`surface_ledger_stale`（清点表里残留已消失的成员，breaking）、`surface_ledger_misclassified`（disposition 与冻结字段自相矛盾，或排除项无理由，breaking）；返回 `classified_ratio` |
| `assert_surface_classified(...)` | 绑定方/CI 可直接调用的硬门（抛 `BindingContractError`） |
| 接线 | `verify()` 与 `verify_entry()` 都把清点结果计入 `checks/matched` 并进 findings；因此 `IceDEM.exchange_state()` / `IceDEM3D.state_dict()` 的导出前置门**自动继承**"面不许静默变化"的性质 |
| `surface_mutation_check()` | 4 个受控变异（新增公开成员 / 清点表缺项 / 冻结成员被标成 excluded / 未改动对照），其中第一行附带**round-1/2 基线对照**：同一变异类喂给旧检查集得 0 findings |
| 审计对象 | 生产门审计**规范冻结类本身**（`entry.module.<entry_name>`），不审计调用方子类——否则用户自己加辅助方法就会被导出拒绝 |
| 顺带修的缺陷 | `verify_entry(target=class)` 缺 `verify()` 已有的类级回退，对一个类目标报出 10 条假 `attribute_removed`；且回退只读单类源码，瘦子类（状态继承自别的模块）仍全红 → 改为沿 MRO 读源码 |

契约数据变了 → 指纹必须**同 commit 重钉**：`sha256:0cbfed8c…4105d` → `sha256:048e4cf9…195cd`（预期摩擦，不是 bug）。

## ⑤ 注意点（踩到的坑）

1. **指纹 churn 是设计而非噪声**：动契约数据必须同 commit 重钉 `FROZEN_FINGERPRINT`，否则 `test_frozen_fingerprint_is_pinned` 红。
2. **"排除"不等于"可以用"**：被排除的诊断成员仍在 `consumer_coverage` 的判定里算 GAP——绑定方碰它照样失败；排除只表示供应方不为它背书。
3. **审计对象必须是规范类**：若按调用方子类审计，`CalibratedIceDEM` / `EnergyAuditedIceDEM3D` 这类仓库内子类（以及用户子类）加个辅助方法就会让导出门失败。故 `audit_surface()` 默认 `target=None` → 解析 `entry.module.<name>`。
4. **类目标路径的假红**：`verify_entry(IceDEM, "IceDEM")` 曾报 10 条假 breaking（实例状态在类上不可见）；修复后仍要注意**瘦子类**——必须沿 MRO 读源码，否则 `class Thin(IceDEM)` 也是全红。
5. **基线必须同变异**：证明"清点是增量"的唯一诚实做法是把**同一个**变异类喂给旧检查集（得 0 findings），而不是拿一个没人检查的样本对比。
6. **局限**：清点只覆盖"公开成员是否存在/被表态"，不覆盖成员**语义**漂移（语义仍由第 1 轮 19 个行为探针 + 数值 benchmark 负责）；跨仓 CI 接线仍属消费方（TensorPhysics）职责，本仓不做。
7. **第 2 轮此前未并入 main**（`c58d8c44` 只在 `agent/m18458`）：本轮把它重新落地，消费方覆盖在本单产物里是活的（`consumer_coverage` 7/7，pin 与上游 adapter sha256 一致）。
