## Findings (severity-ranked)

### F2 — BLOCKING (reproducibility): the committed R3 driver cannot reproduce its own ensemble — **fixed by this audit**
`benchmarks/biaxial_shear_band/run_r3_ensemble.py:150` selected the `post_peak` cumulative reference with an
exact float equality (`abs(s["strain"] - peak_strain) < 1e-9`). `peak["axial_strain"]` is detected at the maximal
deviator step and does not land on the 0.01 snapshot grid (threaded torch reductions move it ~1e-8), so the list
comprehension returned `[]` and `start[0]` raised `IndexError` — **after** the 100 s DEM run, killing the specimen.
Reproduction (m17693 HEAD, unchanged code, `R3_THREADS=4`):

```
File ".../run_r3_ensemble.py", line 150, in _run_one
    ref = start if isinstance(start, dict) else start[0]
IndexError: list index out of range
elapsed 110.6s
```

The same code had produced 5/5 specimens on 2026-11-13 06:59 (git `1d7a0b6e`), i.e. the pass was luck of the
float grid, not robustness. Consequence for m17693's claim “the R3 verdict stands unchanged”: the number is
traceable, but until this audit it was **not reproducible by the shipped code**.
**Fix (m17722)**: `_nearest_snapshot()` + `_cumulative_starts()` (nearest snapshot, `None`-safe), 5 regression tests
`tests/test_r3_ensemble_peak_guard.py` (5 passed in 0.4 s). Post-fix end-to-end run:
`artifacts/board_audit_m17722/r3_anchor_s11_rerun.json` → `anchor_s11` radon **52.50°**, tensor **83.03°**,
production 55.67°, 2 late pairs, 100.7 s — **exactly** the `logs/r3_ensemble.log` line
`[done] anchor_s11 radon=52.50 tensor=83.03 resolved=True (95s)`. Reproducibility restored and the R3 per-specimen
values independently confirmed.

### F3 — MAJOR (evidence packaging): the R3 raw log and artefacts are not in HEAD or in `origin/main`
`logs/r3_ensemble.log`, `artifacts/biaxial_shear_band/r3_ensemble.{json,png}` were committed in `1d7a0b6e`
(branch `agent/m17498`), which is **not an ancestor** of m17693's HEAD and whose artefacts never reached
`origin/main` (gate-filtered on merge). So the primary evidence for 53.83° is only reachable through git history,
and the docs point at a path that does not exist in a fresh checkout. **Remediation**: land a small
`artifacts/biaxial_shear_band/r3_ensemble.json` (regenerated by `summarise_r3_log.py` or by the now-working driver)
with the R3 doc, and add the log line as a test fixture.

### F4 — MAJOR (overstated self-check): mission check #4 asserts a smoke test that measures nothing
Mission `result.evidence.summary` #4 says `run_r4_cumulative_ensemble.py --quick` “单试样冒烟通过 (API/缓存/JSON 写出)”.
Reproduced at HEAD: the specimen finishes in 41.7 s and yields `one_step.n_pairs = 0`, `cumulative = {}`,
`n = 0` in both ensemble summaries, `passed = false`. The driver therefore “passes” while producing **no
measurement**, so the quick path validates plumbing only and must not be counted as a DEM check. Recommendation:
make the quick path fail loudly (`n_pairs < 2` → specimen `status=error`) so future smoke tests cannot go green on
an empty record.

### F1 — MAJOR (bookkeeping): the audit-order anchor slug has no benchmark row
`tensor_benchmark_cases` has **0 rows** with `anchor_slug='CASE-BIAXIAL-SHEAR-BAND'`. The substantive judge for
this case is `id=59`, `anchor_slug='CASE-DEM-BIAXIAL-CELL-KNOWN-ANGLE'`, case_name “TensorDEM plane-strain biaxial
cell (24x48, p=100 kPa, wall_friction 0.55, 4000 consolidation steps) shear-band inclination …”, tolerance
`<15%`, status `passed` (passed_at 2026-11-13 06:13:49Z). Numerically: ref 60° (Desrues & Viggiani 2004, 55–60°),
got 53.83° → 10.3 % **within** 15 %, **not** within 3 %. Because the judge keys on the slug, a literal reading of
the order yields “no judge”. **Remediation**: register an alias row (or rename the slug) so gate and humans agree.

### F5 — NOTE (claim scope, not a defect): the synthetic SNR result is a mechanism, and it over-predicts the observed scatter
R4's headline (one-step 27.20° vs cumulative 0.88° RMS at 0.25 % noise, 30.9×) is reproduced bit-exactly. But R3's
*actual* cross-specimen scatter is 0.90° std with per-specimen mean errors of 8.9–12.5 % — far below the ~12–18°
that the 0.25 % synthetic noise level would produce per specimen mean. Either the DEM displacement field noise is
much smaller than 0.25 % of the 1.5 m spacing, or the homogeneous-jitter noise model is harsher than the case.
The doc already limits the claim (“a mechanism, not an anchor error budget”); the audit confirms that limit is
load-bearing, and the R4 DEM half was rightly left **WITHHELD**.

### F6 — NOTE: external anchor is inherited, not re-verified
The 60° midpoint comes from the pre-declared case sheet (`docs/BIAXIAL_SHEAR_BAND.md:30-31`), i.e. Desrues &
Viggiani 2004 IJNAMG 28:279-321 55–60°. m17693 states this honestly (its own gap 2). The measured 53.83° sits
*below* even the 55–60° band of the cited source, which the 15 % bar (51–69°) absorbs but the 3 % bar does not.
This caps the defensible level at **L4**, not L5.
