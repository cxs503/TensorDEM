# PR #216 cure — merging `agent/m3558` into `main` without losing either side

Mission 4034. This note records why PR #216 was unmergeable, how the single conflicting file was
resolved, and which machine checks make the resolution falsifiable. Nothing here is a "trust me":
the decision record is `artifacts/pr216/verify_pr216.json`, produced by
`scripts/verify_pr216_merge_semantics.py`.

The overlap is the worst one available: `docs/doc_evidence_ledger.json` is a *summary of the whole
`docs/` tree*, generated by `scripts/audit_doc_evidence.py`. Any single-sided resolution therefore
deletes the other side's documents from the evidence audit — the same failure mode as the earlier
mechanical overlay that dropped content silently, which is why this cure is gated on proof.

| parent ledger | documents | pointers | `doc:TRACKED` | `test:TRACKED` | `data:TRACKED` | `figure:TRACKED` |
|---|---|---|---|---|---|---|
| `main` `6c6f98b` | 106 | 521 | 68 | 123 | 26 | 7 |
| `agent/m3558` `d7c946c` | 106 | 543 | 91 | 119 | 27 | 9 |
| **merged** `65294fe` | **107** | **552** | **93** | **124** | **27** | **9** |

Neither parent dominates (main has 4 more `test:TRACKED` pointers, the branch 23 more doc
pointers), so "take ours"/"take theirs" is provably lossy here, not a matter of taste.

## 2. Resolution

```bash
git merge --no-ff github/agent/m3558          # conflict on docs/doc_evidence_ledger.json
git checkout --ours docs/doc_evidence_ledger.json   # placeholder only, overwritten next
python3 scripts/audit_doc_evidence.py         # regenerate from the *merged* tree
git add -A && git commit                       # merge commit 65294fe
```

Why regeneration and not a text merge: the ledger entries carry line numbers, so a hand-merge
would produce a ledger whose line references no longer match the merged documents.
Why not a side-pick: see the table above — 22 pointers (branch) or 4 `test:TRACKED` pointers
(main) would disappear.

The merged ledger (107 documents = 106 + 106 with 105 shared, 552 pointers, 0 orphan) is a strict
union of both parents: 552 ≥ 543 and ≥ 521, the gap to the naive sum (1064) being the 512 shared
pointers.

`docs/doc_numeric_claims_ledger.json` is regenerated as well (`python3
scripts/audit_doc_numeric_claims.py . --write`) because this note itself adds a document; the
ratchet tests in `tests/test_doc_numeric_claims.py` enforce that the committed ledger matches the
tree.

## 5. Caveats

- Regeneration is only sound on a *complete* worktree; C1 proves the merged tree really holds both
  sides' files rather than assuming it.
- `scripts/verify_pr216_merge_semantics.py` pins the four SHAs of this cure. It is a record of
  this merge, not a general-purpose merge linter; another cure needs its constants updated.
- The conflict is documentation bookkeeping only. No solver numerics changed, so the >15 %
  accuracy criterion does not apply to this repair; the test suite is the executable guard, and
  the evidence-chain checks are exact integer comparisons (0 lost pointers, 0 regressions).
