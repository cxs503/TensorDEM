## 1 案例介绍（物理背景 / 几何 / 参数）

TensorDEM 的 SI-2 链路把 TensorFEM 黏结破坏面转成 DEM 初始损伤冰场：简单立方格点铺颗粒、按面内外侧切断键。该模块的三条验收判据（质量守恒、断键面密度、每键断裂能）在 roadmap 里写作"已验收"，但两道**冒烟判据是自证式**的：质量判据拿 `N·ρ·(4/3)πr³` 与建场时同一公式比，机器精度通过却对"DEM 是否承载 FEM 连续体质量"零信息；断键判据把每个破坏面当作**无限平面**，与面的面积/形状无关。

几何与参数（全部可在二进制中精确表示，平面/层重合不是浮点噪声决定的）：

| 参数 | 值 |
|---|---|
| 颗粒半径 r | 0.125 m（量化负控用 0.1 m） |
| 格点间距 s = 2r | 0.25 m（负控 0.2 m） |
| 域 (0, 8s)³ | 2 m × 2 m × 2 m，N = 8³ = 512 颗粒，1344 键 |
| 密度 ρ | 917 kg·m⁻³（冰） |
| 破坏面 | 法向 ẑ，质心 (1,1,0.5)，A = (8s)² = 4 m²，G = 100 J·m⁻² |
| 连续体体积 V_FEM | 8 m³ ⇔ ρV = 7336 kg |

## 2 怎么做的（方法 / 流程 / 工具链）

1. **定位欠账**：`pytest --co` 显示 **5 个测试模块在 collection 阶段即 ImportError**（958 项可收集，5 错）。逐条归因后确认是同一机制：`m2245/m2269/m2298/m2247` 的提交说明自述"N 个文件被门禁滤除"——审计测试落了盘、被审计的实现没落盘，于是"有测试无代码"。
2. **本单只清偿其中无人认领的一块**：`tests/test_fracture_gen_mass_footprint.py`（m2245）缺失的 `MASS_RADIUS_FACTOR / face_footprint_radius / FailureFace.extent_radius / FractureLedger.mass_accounting / mass_mapping="lattice_cell"`。Hertz、恢复系数、摩擦锥三个模块正由其它在飞单处理，本单不碰。
3. **恢复来源**：门禁丢弃的实现残留在未合并分支 `agent/m2419`（commit `721041a`）上，其父提交与当前 main 的 `fracture_gen.py` **逐字节相同**，因此移植无冲突、不引入 main 之外的语义。本单取该实现为基，但**否决了它的一处契约变更**（见 §5.1），保留仓库默认路径为冻结的 `equal_volume_spheres`。
4. **独立复核**：`scripts/verify_fracture_gen_restore.py` 用**闭式/枚举表达式**重算基准（质量分数 π/6−1、量化亏损 1−0.4³/0.5³、柱枚举计数），只调用模块公开 API 读数，不用模块自己的辅助函数自证；一次性给出 7 项判据 + 2 项一致性/负控，程序化写 JSON 与图。

## 3 计算结果

见 `docs/fracture_gen_restore/verification.json`（全部数字由上脚本程序化生成，无手抄）。要点：

- 冻结默认映射相对连续体质量亏损 **−47.64 %**，远超平台 15 % 验收线，`within_15pct=False`（判据如实 FAIL）。
- 选用 `lattice_cell` 后亏损 **0（机器精度）**：修正由"质量半径"承载，`mass_radius/r = 1.240701 ≈ (3/4π)^{1/3}·2`，`particle_mass = ρs³ = 14.328125 kg` 精确。
- 有限足迹断键：R_face/s = 0.5/1/2/3/5/10 对应 0/4/12/32/64/64 键，与格点柱枚举**逐档零偏差**；
  **无限平面口径的相对过度切断**为 ∞（0 键面）/16×/5.33×/2×/1×/1×——即面越小，旧口径越离谱，
  这正是"把有限破坏面当无限平面"对初始损伤状态的系统性放大。
- R_face 覆盖全截面时足迹口径与平面口径一致（64 = 64），说明修复没有顺手改掉平面极限。

## 5 注意点（踩过的坑 / 局限 / 适用范围）

1. **不能用"改测试"换绿灯**：未合并的 `721041a` 把仓库默认映射翻成 `cell_volume`，并把两份审计测试改成显式选 `equal_volume_spheres`。那会让已发表的断裂场工件不可复现，等于用测试迁就实现。本单改为：默认保持冻结映射、守恒映射 opt-in，两份测试的断言原样保留。
2. **一处真·测试缺陷（已修，1 行）**：`tests/test_fracture_gen_audit.py` 的量化判据要求 `relative_error` 为 **正**，而同一模块冻结判据要求 `relative_error = π/6−1` 为 **负**——同一字段的符号被两处要求相反，不可能同时成立。按物理约定（`dem−fem`，亏损为负）保留符号，量化判据改用 `abs()` 比较幅值，并在代码注释里写明理由。
3. **局限**：本单复核的是"实现是否满足其解析判据"，不是"该映射在真实冰场里更准"。`lattice_cell` 只在格点整除域上严格守恒（负控 L=0.5 m 时仍有 −48.8 % 量化亏损），非整除域必须显式报告 `lattice_volume_covered` 与 `domain_volume` 之差，否则会得到虚假的 0。
4. **未清偿的相邻欠账（如实记录）**：`tests/test_dem3d_hertz_contact.py`、`tests/test_dem3d_restitution.py`、`tests/test_friction_cone_verification.py`、`tests/test_tangential_friction_verification.py` 仍为 collection ImportError；`tests/test_ice_floe_physics.py` 在 main 上有 **16 个预存失败**（`benchmarks/ice_floe_physics.py` 的 m2203 补丁同样被门禁滤除），经 stash 复原验证与本单改动无关，也不在本单范围。
5. **属交付管线缺陷**：同一批实现被门禁丢弃后，测试永久转红、修复分支合并不了（`agent/m2419` 停在未合并状态）。按 2026-11-02 控仓令，本单只记录、不改平台。
