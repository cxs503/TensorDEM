## 1. 案例介绍

### 1.1 物理背景

DEM 的显式积分步长由**最硬的那个接触**决定（Cundall 判据 `dt ≤ 2√(m/k)`）。
冰-结构、摩擦 jamming、多材料混合等场景里，装配体内同时存在刚度差 10~100 倍的接触
（骨架刚度 vs 主体刚度），于是"为了 10 % 的接触把全局步长压到 1/10"就成了主要成本。
多速率（multiple-time-step, MTS）把力按**速率类**拆开：硬接触在细步上重算，软接触与
历史变量（切向位移 ξ、滚动角）在粗步上推进一步，粗步由**可机读的时间步契约**给出。

本节点把一个"能算"的原型推成"能交付"的模块，并且把成本判据做成机器可裁决的：
**同样物理时段内墙钟 ≥2×，而 jamming 密度 φ_J 不变**。

### 1.2 几何与参数（全部取自 acceptance.json）

| 量 | 取值 |
|---|---|
| 颗粒数 N | 256 |
| 初始（压实后）边长 L | 0.322717 m |
| 出货引擎步长 dt_engine | 2.2060e-05 s |
| 法向刚度 kn | 3.0e4 N/m |
| 切向刚度比 kt/kn | 0.5 |
| 滚动摩阻 μ_r | 0.05 |
| 摩擦系数 μ | 0.5 |
| 接触阻尼 ζ | 0.4 |
| 刚度层级（stiff_ratio） | 10 子步 → 见 §2.2 |
| 子步数 n_sub（层级 100:1） | 10 |
| 伺服压力阶梯 | [300.0, 100.0, 30.0, 10.0, 3.0, 1.0] |
| 每级步数 × η | 2500 × η=150.0 |

### 1.3 时间步契约（本节的判据就是"门"本身）

| 量 | 定义 | 取值 |
|---|---|---|
| `dt_c` | 接触时间尺度：Hertz 由 `hertz_impact_time.hertz_contact_time` 给出，线性弹簧由 `contact_timestep_ledger.cundall_critical_timestep` 给出 | 每对接触按刚度分别计算 |
| `ratio` | `dt / dt_c` | 请求步长与接触尺度的比 |
| `n_sub` | `ceil(ratio / margin)` | 契约**要求**的子步数 |
| `margin` | 单速率可接受上限 | 0.05（1e5 步账本用 0.05；jamming 用 0.10） |
| 紧性阈值 | `ratio ≥ 0.5` 判**不可采纳** | 0.5（负控，见 §3.5） |

`dt/dt_c = 0.5` 是**负控**：一个"接受 0.5 步长的门"不是门。本节点要求它在
restitution 上给出 >10 % 的可检测失效（§3.5）。

## 2. 怎么做的

### 2.1 方法链

1. **契约层**（P82W2-N09 已交付，本节点复用并加固）：`StabilityGate` +
   `hertz_gate/hooke_gate/friction_gate/cundall_gate`；`setup_timestep` 把契约
   写进 `self.dt / self.n_sub`，并在 `ratio ≥ 0.5` 时抛 `InadmissibleTimeStep`。
2. **积分器层**（本节点的两处工程改动，见 2.2）：`MTSDisks`，慢臂=软接触+墙上接触+
   外力（每粗步一次），快臂=硬接触（每子步一次），子步内做摩擦锥 return mapping。
3. **验收层**：`benchmarks/mts_speedup_gate.py` 跑 a~e 五条判据，把每个数字写进
   `artifacts/P82W5-N07/acceptance.json`；`scripts/mts_speedup_gate_figures.py` 从
   JSON 出图；本文件由 `scripts/mts_speedup_gate_report.py` 从 JSON 生成。
4. **回归层**：`tests/test_mts_speedup_gate.py`（13 条）钉住(a)融合内核与参考实现
   的逐项等价（力/力矩/ξ/roll 到 round-off）、(b)墙接触的速率归类、(c)契约与负控、
   (d)速率契约的计数可观测性。

### 2.2 两处工程改动（这就是"把成本压回来"的全部内容）

**改动 1：墙接触归慢臂。** 墙的法向刚度是 `kn`——**软类**。旧实现把墙放在快臂，
每粗步重算 `n_sub` 次（jamming 场景下 16.9 ms/粗步里有 ~10 ms 是墙），
精度上没有任何收益。现在墙接触随软臂每粗步一次（`wall_rate="slow"`，默认），
`wall_rate="fast"` 保留为消融对照。

**改动 2：快臂融合内核。** 每粗步做一次**成对静态量**预计算（刚度、有效质量、阻尼
系数、切向/滚动模量、力臂半径，`_prepare_fast`），子步内只做一次扫掠（`_fast_step`），
把三趟（几何/运动学/摩擦）合成一趟。接触律不变：
`tests/test_mts_speedup_gate.py` 证明融合内核与参考组合在力/力矩/ξ/roll 上一致到
≤1e-11 相对（本机实测 ~1e-13）。

**顺带修掉的两个缺陷**（都是"静默错"，不报错但改结果）：

- `stress_tensor` 里 `len(self._xi) == len(keep)` 把**候选对数**与**接触对数**比较，
  恒为假 ⇒ 摩擦份额**从未进入 virial**。而伺服控制的正是 `P`，于是它追着一个偏低的
  读数停在更密的堆积上。已改为按 `sel = flatnonzero(keep)` 取 `_xi[sel]`。
- 墙接触集合（`_wall_sets`）只在第一次调用时建立、之后**从不更新**（旧路径），
  远离墙的颗粒入场后拿不到墙力。现在每粗步重建（`work["wall"]` 计数可查，测试钉住）。

### 2.3 消融矩阵（"改动前后"的对照基线）

| 变体 | 墙归类 | 快臂内核 | 说明 |
|---|---|---|---|
| legacy | fast | reference | P82W2-N09 的实际行为（=改造前基线） |
| walls_fast_lean | fast | lean | 只换内核 |
| walls_slow_reference | slow | reference | 只换墙归类 |
| matured | slow | lean | 本节点交付（默认） |

### 2.4 jamming 的协议对齐（为什么必须对齐）

φ_J 是**协议相关**量：同一个势能面，从不同路径压到同一压力，会得到不同的边缘稳定态。
因此本节点把 φ_J 比较做成**协议对齐**：

- 初态、压实（`P=3e3`）、阶梯压力序列、每级物理时长（`steps_per_level × dt_engine`）、
  伺服 η、伺服**盒缩速率上限**（`3e-4`/engine-step）全部取 W4-P1 锚
  `jamming_density_isotropic` 的同款参数；
- 分支点额外做一级 `P=3e3→300`（用**出货单速率引擎**跑，即锚自己的那一级终点），
  两个积分器从**同一状态**分支出去，剩下的差别只有积分器；
- 伺服压力口径对齐：锚的 `virial_tensor` 只统计颗粒-颗粒接触，因此验收跑里
  `pressure_includes_walls=False`（同一状态两口径相差 9.6 %，见 §5.3）。

不做这一级"条件化"时，第一级 `P=3e3→300` 是 φ 0.98 的剧烈回弹，两个积分器在此
播下不同堆积，jamming 态把这段记忆保留下来——这条路径的偏离量作为
`c3_transient_sensitivity` 一并报告（见 §3.4），**不隐藏**。

## 5. 注意点（踩过的坑 / 局限 / 适用范围）

1. **我自己的融合内核一开始力矩符号错了**：`lever_j = +r_j n` 且作用在 j 上是 `-total`，
   故 j 的力矩是 `-r_j·(n×f)`。第一版写成 `+r_j`，力对（1e-13）而力矩错（11.8 vs 尺度 6.8）。
   若只有"能量/压力"判据，这个错会被掩盖——所以回归测试必须钉**力矩**。
2. **融合内核的配平陷阱**：先用 `force[:,0] = bincount(...)` 写过墙力（覆盖而非累加），
   墙力被静默清零；靠"同一状态两速率归类力必须相等"的测试才暴露。
3. **两口径压力差 9.6 %**：同一状态，`MTSDisks` 若把墙接触计入 virial 得 297.6 N/m，
   出货 `virial_tensor` 只统计颗粒-颗粒得 271.5 N/m。伺服控制的是哪个口径，直接决定
   它停在多密的堆积上（φ_J 差 ~2.7 %）。因此新增 `pressure_includes_walls` 开关，
   与哪个阶梯比就把口径对齐到哪个。
4. **伺服盒缩速率上限是协议的一部分**：出货伺服是"每 engine 步 ≤3e-4"，换算成速率是
   `3e-4/dt_engine`；MTSDisks 原先用裸速率上限 35 /s，在粗步上等于把盒缩速率放大 n_sub 倍，
   首级卸载会把堆积"炸"出不同的记忆。已按 engine 步对齐（`JAM_MAX_STEP`）。
5. **φ_J 是路径相关的**：非平衡瞬态分支（φ=0.98 直接卸到 300）里两积分器的堆积会分叉，
   |Δφ_J| 达 0.22 %；
   条件化分支把这项消掉到 0.0081 %。**结论只对"从同一状态分支"成立**，
   这是适用范围，不是可以外推的普适常数。
6. **未修完的引擎差异（本节点的诚实缺口）**：`MTSDisks` 与出货 `DiskSystem` 在
   同协议、同起点、同 dt 下 φ_J 相差 ~2.7 %（单速率臂同样偏），本节点只证明了
   "MTS 分裂不引入偏差"，**没有**把引擎偏差收敛到 0.5 % 以内。下一步应做引擎逐项对齐
   （墙切向律、滚动阻力公式、积分器一步的力评价顺序），并把结果登记进 capability ledger。
7. **墙切向状态在粗臂上是 O(dt) 近似**：Cundall-Strack 切向弹簧 + 锥返回映射在粗步上
   积分一次，与子步积分相比在饱和接触上有几个百分点的瞬时差（测试钉住 ≤5 %），
   对 φ_J 的影响未检出。
8. **适用范围**：二维圆盘、线性法向弹簧 + 切向 Cundall-Strack、刚度层级 ≤100:1、
   粗步 `dt/dt_c ≤ 0.1`。三层以上刚度层级或 Hertz 非线性法向未在本节点验证。

## 6. 误差判定（逐项，显式回答"是否 <3%"）

| 关键量 | 基准 | 误差 | <3 % ? | 说明 |
|---|---|---|---|---|
| restitution（e=0.5，dt/t_c≤0.2） | 同 alpha 的收敛解（dt/t_c=5e-4） | 0.58 % | 是 | 判据 ≤2 %，全阶梯通过 |
| restitution（e=0.9，dt/t_c≤0.2） | 同上 | 0.18 % | 是 | 同上 |
| 能量漂移（MTS，1e5 步） | 初始总能量 | 0.73 % | 是 | 判据 ≤1 % |
| 线动量相对变化（MTS，1e5 步） | 初始线动量 | 2.22e-14 | 是 | 判据 ≤1e-12 |
| φ_J：MTS vs 单速率（同引擎） | 单速率同协议 | 0.0081 % | 是 | 判据 ≤0.5 % |
| φ_J：MTS vs W4-P1 锚 | `jamming_density_isotropic` | 2.77 % | **否** | honest FAIL：与单速率臂的偏离同量级（引擎级） |
| φ_J：单速率臂 vs W4-P1 锚 | 同上 | 2.76 % | **否** | 对照量，证明偏离非 MTS 引起 |
| 墙钟加速（同物理时段） | 单速率基线 | 3.31× | 不适用（比值越大越好） | 判据 ≥2× |

**总结**：判据 a/b/c-speed/c-φ_J(同引擎)/d/e 全部通过；**c-φ_J vs W4-P1 锚不通过**，
原因是 `MTSDisks` 与出货引擎之间的引擎级 φ_J 偏移（2.7 %），单速率臂同样偏离，
与 MTS 分裂无关。这条按 honest FAIL 记录，不做覆盖，下一步动作见 §5.6。
